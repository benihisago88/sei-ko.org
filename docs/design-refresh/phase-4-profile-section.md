## 1. ゴール

このサイトは「専任担当を雇うほどではない小さな会社・個人事業主」に向けて、「何をお願いすればいいか分からなくても大丈夫」と繰り返し訴えている。にもかかわらず、**誰が対応するのかを説明するセクションが1つもない**。

現状で運営者に触れているのは以下だけ:

- ヘッダー／フッターの「運営：誠幸（セイコウ）」という小さな添え字
- 構造化データ（`ProfessionalService`）の `name`
- フッターの著作権表記

小規模事業者が個人に仕事を頼むかどうかを決める場面で、**相手が見えないことは最大の離脱要因**になる。FAQで「小さな修正でも大丈夫」と答えても、それを言っているのが誰なのか分からない。

### 顔写真は使わない（確定方針）

オーナーの判断で、**顔写真なしのテキスト版**で実装する。写真枠・プレースホルダー画像も置かない。

代わりに、**ブランドマーク（円形＋担）を大きく置く**ことで視覚的な「人格」を作る。

**このフェーズが完了すると:**

- `#faq` と `#contact` の間に、対応者の考え方・進め方・対応範囲を伝えるセクションが入る
- 訪問者が「どういう人に頼むことになるのか」を、問い合わせ前に把握できる

## 3. 作業手順

### Step 1: 掲載内容をユーザーから聞き出す【必須・最重要】

**このステップを飛ばして本文を書き始めないこと。**

`00-common-constraints.md` のとおり、**経歴・実績・対応年数・保有スキル・資格などは、運営者本人しか知らない事実**。AIが推測で書くと、事実と異なる内容が公開されたまま気づかれない可能性がある。これは訪問者への虚偽表示になる。

ユーザーに以下を質問し、**回答が得られたものだけを掲載する**。

| 項目 | 用途 | 必須 |
|---|---|---|
| 対応者の呼称 | 「誠幸（セイコウ）」で良いか。個人名を出すか | 必須 |
| バックグラウンド | どういう経緯でこの仕事をしているか（1〜2文） | 推奨 |
| 得意領域 | WEB / EC / AI のどこが強いか、逆に苦手・受けない範囲 | 推奨 |
| 仕事の進め方の信条 | 「全面リニューアルを勧めない」など、既にサイトに出ている姿勢の裏付け | 推奨 |
| 経験年数・実績数 | 出せる数字があるか。**なければ書かない** | 任意 |
| 対応できないこと | 断る領域を明示すると信頼が上がる | 任意 |

**回答が得られなかった項目は、本文に書かず `<!-- TODO(user): ... -->` のHTMLコメントで空欄として残す。** 「〇〇年の経験」のような当たり障りのない表現でも、事実確認が取れていなければ書かない。

### Step 2: 既にサイトに書かれている事実は再利用してよい

以下は**既にこのサイト上に記載済み**なので、運営者の確認なしに使ってよい（新たな主張を作っていないため）。

| 内容 | 出典 |
|---|---|
| 全国オンライン対応 | `index.html` の `.trust-row` |
| 夜間・土日対応可 | 同上 |
| 小さな相談からOK | 同上 |
| 通常2営業日以内に返信 | `.form-note` |
| 原則オンライン・非同期で進行。必要な場合のみオンラインミーティング | `.process-note` |
| 着手前に料金を提示。相談だけで費用は発生しない | `#pricing` のリード文 |

**ただし、これらを単に繰り返すだけのセクションにはしないこと。** 重複した情報を読ませるだけになる。あくまでStep 1で得た本人の言葉が主役で、これらは補強に使う。

### Step 3: HTMLを実装する

構造の例（**文言は Step 1 の回答で埋めること。下記のリード文はあくまで骨組みの例**）:

```html
    <!-- 運営者紹介: 誰が対応するのかを明示 -->
    <section id="about" class="about section-wrap section-pad">
      <div class="about-box reveal">
        <div class="about-mark" aria-hidden="true">担</div>
        <div class="about-body">
          <p class="eyebrow"><span></span> WHO WE ARE</p>
          <h2>
            <span class="nobr">対応するのは、</span>
            <br class="pc-only" />
            <span class="nobr"><em>ひとりの担当者です。</em></span>
          </h2>
          <!-- TODO(user): バックグラウンドを1〜2文で -->
          <p>（Step 1 で得た内容）</p>
          <dl class="about-facts">
            <div><dt>対応範囲</dt><dd>WEB制作・改善 / Shopify・EC / AI・業務効率化 / ツール選定</dd></div>
            <div><dt>進め方</dt><dd>原則オンライン・非同期。必要な場合のみオンラインミーティング</dd></div>
            <div><dt>返信</dt><dd>通常2営業日以内</dd></div>
            <!-- TODO(user): 対応できない領域があれば1行追加 -->
          </dl>
        </div>
      </div>
    </section>
```

**実装上の注意:**

- `.about-mark` の「担」は装飾なので `aria-hidden="true"` を付ける（ヘッダー・フッターで既に同じ文字が読み上げられるため、三重読みを防ぐ）
- 見出しは既存パターンどおり `nobr` + `pc-only` + `<em>` を使う
- `reveal` を付けてスクロールアニメーションを既存と揃える
- `<dl>` を使うのは、項目名と値の対応が明確な情報だから。`<div>` でラップするのは `<dl>` 内で flex/grid レイアウトを組むための標準的な書き方

### Step 4: ナビゲーションに追加するかを判断する

ヘッダーのナビは既に6項目（できること / 活用イメージ / 料金 / AI活用ガイド / よくある質問 / お問い合わせ）あり、**これ以上増やすとモバイルで窮屈になる**。

**デフォルトでは追加しない。** 追加したい場合はユーザーに確認する。

### Step 5: CSSを実装する

`styles.css` の **11. FAQ と 12. お問い合わせフォームの間**（1154行の直前）に新セクションを追加する。

```css
/* ==========================================================================
   12. 運営者紹介
   ========================================================================== */
```

そして**冒頭の目次コメント（5〜20行）にも追加し、以降の番号を繰り下げる**（12→13, 13→14 …16→17）。本文中の見出しコメントも合わせて振り直す。

スタイルの方針:

- 背景は `--sand`（`#f4f8f9`）または `--mint`（`#e7f8fa`）。**前後のFAQ・お問い合わせと背景が同じにならないように**する
- `.about-mark` は `.brand-mark`（`styles.css:134`）の拡大版。`background: var(--ink)` / `color: #fff` / `border-radius: 50%` / 72〜96px程度
- `.about-facts` の `dt` はラベル扱いなので `--mono` + `letter-spacing` + `--muted`。既存の `.card-number` / `.plan-label` のトーンに合わせる
- レスポンシブ: 768px以下でマークと本文を縦積みにする。`styles.css:1420` 以降のレスポンシブセクションに追記する

`styles.css` を変更したので、4ページ分のクエリを上げる。

## 4. やってはいけないこと

- **経歴・実績・年数・資格を推測で書く** — このフェーズで最も重大な禁止事項。裏が取れない情報は `<!-- TODO(user): -->` にする
- **「10年以上の経験」「100社以上を支援」のような具体的な数字を例文として置く** — 消し忘れてそのまま公開される事故が実際に起きる。数字を使うなら必ず `TODO(user)` コメントとセットにする
- **写真・イラスト・アバター画像を追加する** — 写真なしが確定方針
- **既存セクションの文言を書き換える** — 新規セクションの追加だけが担当範囲
- **`#faq` / `#contact` の構造を変える** — 挿入するだけ
- **ナビゲーションにユーザー確認なしで項目を追加する**
- **`styles.css` の目次コメントを更新せずにセクションを足す** — 番号がずれたまま残る
- **`git commit` しない**

```bash
grep -n "^ \* [0-9]*\. " styles.css
grep -n "^   [0-9]*\. " styles.css
```

**期待結果**: 目次（前者）と本文の見出し（後者）で、番号とタイトルが1対1で一致し、通し番号に飛びがない

```bash
grep -rn "styles.css?v=" --include="*.html" . | grep -v "^./docs"
```

**期待結果**: 4行すべて同じ値

### 6-5. 目視確認
